# Inspect an installation

Run `t1os capabilities` as the guest's `t1os` operator, or `t1os capabilities --json` for machine-readable output. The exit status indicates whether the inventory ran, not whether every capability is ready. The profile comes from the installed release marker; an older or absent marker produces `unknown`, not an inferred minimal installation.

Each row separates installed artifacts, configuration evidence, prerequisites and the scope of its readiness claim. `missing` includes a prerequisite that did not match the required revision or file type. `unknown` means the caller could not establish the evidence. Missing prerequisites or a known inactive service produce `blocked`; `not verified` does not mean a failure. A service reported ready is active locally, not certified end to end.

The inventory reads bounded local metadata; it does not dump settings or read keys. It queries only local systemd units, does not start services, and checks the KVM API without creating a VM. It does not run ADB, launch a browser or emulator, contact a provider or tailnet, run a container, or perform rollback. Native desktop CUA has no integrated backend. The full profile includes the sandboxed browser fixture and Playwright Core. As a non-root user, run `t1os browser check example --chromium /absolute/path/to/chromium` with a trusted Chromium 158.0.8127.18 executable. It uses a dedicated per-workspace fixture profile and a loopback page, not a personal browser profile. Passing proves this fixture works, not native CUA or an always-on browser service.
